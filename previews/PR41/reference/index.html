LatticeProteins.LatticeProteins — Module
LatticeProteins

Simulate the lattice proteins model on a 3×3×3 cubic lattice in Julia.

A lattice protein is a simplified model where a protein sequence of 27 amino acids folds on a 3×3×3 cubic lattice. The energy of a sequence in a given structure is determined by pairwise contacts using the Miyazawa-Jernigan interaction matrix. The probability that a sequence folds into a structure is a Boltzmann distribution over all 103,346 compact structures of the lattice, which compete to fold the sequence.

The public API is the list of exported names, plus the sequence length L, which is declared public but not exported (see names(LatticeProteins)). Everything else is internal and can change in any release.

References

  • Jacquin, Hugo, et al. "Benchmarking inverse statistical approaches for protein structure and design with exactly solvable models." PLoS computational biology 12.5 (2016): e1004889.

Public API

The public API is the model in which all 103,346 compact structures of the lattice compete to fold a sequence. It consists of the names below. They are exported, except L, which is declared public and accessed as LatticeProteins.L.

Sequences

Sequences are strings of amino acids, integer-coded vectors (potts) or one-hot encoded arrays (onehot). Energies and samplers work with integer-coded sequences.

Structures

A structure is referred to by its index among all compact structures.

LatticeProteins.enumerate_structures — Function
enumerate_structures()

The set of all compact structures of a 27-mer on the 3×3×3 cubic lattice: all the self-avoiding walks visiting the 27 lattice sites, modulo the 48 rotations and reflections of the cube. There are length(enumerate_structures()) = 103,346 of them, and a structure is referred to by its index in this set; contact_map gives its contacts.

The chain direction is kept: reversing the chain maps contact (i, j) to (28 - j, 28 - i), which in general gives a different contact map, so a structure and its chain reversal count as distinct structures (62 of them are their own reversal).

The structures are enumerated once, in a fixed order, when the package is precompiled: calling this function costs nothing, and always returns the same object.

References

  • Shakhnovich, E. I., and A. M. Gutin. "Enumeration of all compact conformations of copolymers with random sequence of links." The Journal of Chemical Physics 93.8 (1990): 5967-5971.

Energy and folding probability

LatticeProteins.MJ — Constant
MJ

The 20×20 Miyazawa-Jernigan contact energy matrix (a Matrix{Float64}). Element (a, b) is the interaction energy between amino acids a and b, indexed as in integer-coded sequences (see potts): the amino acids are in the order "CMFILVWYAGTSNQDEHRKP".

source
LatticeProteins.energy — Function
energy(s, seq)

Contact energy of amino acid sequence seq in structure s: the sum of the Miyazawa-Jernigan interaction energies (MJ) over the pairs of residues in contact in that structure (contact_map).

seq is a vector of length 27 of amino acid indices in 1:20 (see potts), and s the index of a structure, between 1 and 103,346 (see enumerate_structures).

LatticeProteins.pnat — Function
pnat(s, seq)

Probability that sequence seq folds into structure s. Equivalent to exp(log_pnat(s, seq)).

source
LatticeProteins.log_pnat — Function
log_pnat(s, seq)

Log-probability that sequence seq folds into structure s (the "native" structure), as opposed to any of the other compact structures.

The probability is a Boltzmann distribution at temperature 1 over all 103,346 compact structures of the lattice (enumerate_structures):

\[\log P_\text{nat}(s \mid \text{seq}) = -\log \sum_{s'} \exp\bigl(E(s, \text{seq}) - E(s', \text{seq})\bigr)\]

See also pnat, energy.

Sampling

LatticeProteins.metropolis! — Function
metropolis!(seq, s; β = 1, nsteps = 1, rng = default_rng())

Perform Metropolis Monte Carlo sampling on the amino acid sequence seq, targeting structure s. The sequence is mutated in place, and returned.

Each step proposes to mutate a random position to a different amino acid, chosen uniformly among the other 19. The move is accepted or rejected using the Metropolis criterion with inverse temperature β, where the energy is -log_pnat(s, seq). The stationary distribution is thus proportional to pnat(s, seq)^β.

The energies of seq in all structures are kept and updated incrementally after each mutation, so a step costs much less than a call to log_pnat. They are computed from scratch at the start of each call: prefer one call with a large nsteps to many short ones.

Arguments

  • seq: integer-coded amino acid sequence of length 27 (values in 1:20).
  • s: index of the target structure, between 1 and 103,346.
  • β: inverse temperature (higher values favor sequences that fold into s).
  • nsteps: number of Monte Carlo steps to perform.
  • rng: random number generator.

See also sample_msa, parallel_tempering.

source
LatticeProteins.sample_msa — Function
sample_msa(s; nseqs = 1, β = 1, nsteps = 1000, rng = default_rng())

Sample a multiple sequence alignment (MSA) of nseqs sequences that fold into structure s, using Metropolis Monte Carlo sampling.

Each sequence is initialized randomly and then evolved independently for nsteps Metropolis steps at inverse temperature β (see metropolis!). Returns a Matrix{Int} of size (27, nseqs), where each column is an integer-coded amino acid sequence.

The sequences are independent, but each is a sample of the distribution pnat(s, seq)^β only if nsteps is long enough for a chain to equilibrate. At strong selection (large β) it is not, in practice: use parallel_tempering.

See also metropolis!, parallel_tempering.

LatticeProteins.parallel_tempering — Function
parallel_tempering(s; betas, nseqs=100, burnin=1000, thin=10, local_steps=10,
                   initial_seqs=nothing, rng=default_rng(), threaded=true,
                   rng_mode=:per_temperature)

Sample sequences with replica exchange, targeting pnat(s, seq)^betas[end] for the structure of index s. betas must contain at least two finite, nonnegative, strictly increasing inverse selection temperatures (hot to cold). The physical folding temperature stays at 1, and all 103,346 compact structures compete, just as in log_pnat.

One round performs local_steps Metropolis steps per replica (the moves of metropolis!), then proposes swaps on alternating disjoint adjacent edges. For two replicas the only edge is attempted every round. A swap is accepted with min(1, exp((betas[i]-betas[j]) * (E[i]-E[j]))), where E = -log_pnat.

Discard burnin rounds, then save the coldest sequence after every thin rounds until nseqs samples have been saved. Thus each replica receives (burnin + nseqs * thin) * local_steps mutation proposals. initial_seqs, when provided, is a (27, length(betas)) integer matrix, ordered hot to cold; it is copied. Otherwise each replica starts from an independent uniform sequence. Use an explicit RNG for reproducible runs. By default, each temperature slot uses its own Xoshiro stream seeded from rng; swaps use rng serially. For fixed arguments and Julia version, results do not depend on thread count or scheduling.

With threaded=true, local updates run on Julia's default thread pool (start Julia with e.g. --threads=4). Set threaded=false when parallelizing independent ladders in the caller. Both modes use the same per-temperature streams and produce identical results.

rng_mode=:shared with threaded=false uses rng for both local updates and swaps, without creating temperature streams. This makes a run resumable: a call with burnin=0 that passes the same RNG and the final_seqs of the previous call continues its trajectory exactly, provided the previous call ended on an even number of rounds (which preserves the alternation of the swap edges). It is also the RNG protocol of v2.1.0 and of the saved Tubiana PT alignment. The default :per_temperature mode creates fresh local streams on each call and is not a checkpoint interface.

Returns a named tuple with:

  • samples: coldest-replica MSA, size (27, nseqs). Samples can be correlated.
  • betas: the fixed ladder used in the run.
  • rng_mode: the RNG protocol used (:per_temperature or :shared).
  • log_pnat, replica_ids: (length(betas), nseqs) traces at saved rounds. Rows follow temperatures; IDs follow sequences through swaps.
  • final_seqs, final_log_pnat: final states at every temperature.
  • burnin_diagnostics, diagnostics: separate burn-in and production counters. local_attempts/local_accepts are indexed by temperature; swap_attempts/swap_accepts by adjacent edge. round_trips is indexed by replica ID and counts completed hot→cold→hot trips entirely within that phase.

Inspect swap acceptance, round trips, and agreement between independent runs. High folding probabilities or accepted swaps alone do not establish equilibrium. Tune the ladder in pilot runs, then hold it fixed for production sampling.

See also metropolis!, sample_msa.

Internals

Not part of the public API

The names in this section are internal: they are documented because the documentation, the figure scripts and the tests use them, but they can change or disappear in any release.

Other sets of competing structures

Internally, the structures that compete to fold a sequence form a StructureSet. Every function of the public API that takes a structure index also accepts a keyword argument structures, by default enumerate_structures(); the index then refers to that set. This is how the documentation reproduces the model of Jacquin et al. (2016), where only a subset of 10,000 structures compete (shakhnovich_structures).

LatticeProteins.StructureSet — Type
StructureSet(contact_maps)

A set of structures competing to fold a sequence. contact_maps is a vector with one contact map per structure: a matrix of size (ncontacts, 2) whose rows are the pairs of residue positions (in 1:27) in contact. All structures must have the same number of contacts.

The functions that take a structure index (contact_map, energy, pnat, metropolis!, parallel_tempering, ...) accept the set of competing structures as the keyword argument structures, and the index then refers to that set. The package has two sets:

  • enumerate_structures(): all 103,346 compact structures of the lattice (the default);
  • shakhnovich_structures(): the subset of 10,000 structures used by Jacquin et al. (2016).

length(S) is the number of structures of a set S, and structure_index finds a structure in a set, which translates indices between sets.

This type and the structures keyword are internal: the public API is the model with all compact structures.

Example

# two structures with a single contact each
S = StructureSet([[1 4], [1 6]])
pnat(1, seq; structures = S)

LatticeProteins.shakhnovich_structures — Function
shakhnovich_structures()

The StructureSet of the representative subset of 10,000 compact structures selected by the Shakhnovich group (Heo, Maslov & Shakhnovich, 2011) out of the 103,346 of enumerate_structures, and used as the set of competing structures by Jacquin et al. (2016) and Tubiana et al. (2019).

Pass structures = shakhnovich_structures() to pnat, metropolis! and related functions to compete only against this set, as in those papers and in the Hugo_MSA_pnat values. Structure indices refer to the set in use; use structure_index to translate between the two sets. For example, structure_index(shakhnovich_structures(), STRUCTURE_A) gives the index (625) of reference structure A in this set.

The contact maps are downloaded the first time this function is called, and the set is built once per session. Internal: the public API is the model with all compact structures.

References

  • Heo, M., Maslov, S., and Shakhnovich, E. "Topology of protein interaction network shapes protein abundances and strengths of their functional and nonspecific interactions." Proceedings of the National Academy of Sciences 108.10 (2011): 4258-4263.
  • Jacquin, H., et al. "Benchmarking inverse statistical approaches for protein structure and design with exactly solvable models." PLoS Computational Biology 12.5 (2016): e1004889.

LatticeProteins.structure_index — Function
structure_index(S::StructureSet, cm::AbstractMatrix)
structure_index(S::StructureSet, s::Integer; from = STRUCTURES)

Internal. Index within the set S of the structure with contact map cm, or nothing if it is not there. cm is a matrix of contact pairs as returned by contact_map; the order of the contacts and the order within each pair are ignored.

The second method looks for structure s of the set from (by default enumerate_structures()), and so translates structure indices from one set to another.

Example

S10 = shakhnovich_structures()
a = structure_index(S10, STRUCTURE_A)  # 625: index of structure A in the subset
pnat(a, seq; structures = S10)

LatticeProteins.Hugo_MSA_path — Function
Hugo_MSA_path(which::Symbol)

Return the file path to one of the reference MSA datasets from Jacquin et al. (2016). Internal, like the other Hugo_MSA functions: these alignments were sampled against the subset of 10,000 structures (shakhnovich_structures), not the full model. which must be one of :A, :B, :C, or :D, corresponding to the four reference structures (STRUCTURE_A, etc.). The files are downloaded the first time one of them is requested.
