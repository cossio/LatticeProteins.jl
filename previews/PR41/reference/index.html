Reference

This page documents the public API of LatticeProteins.jl: the names declared public in the package. None of them are exported, so they must be accessed with the LatticeProteins. prefix or imported explicitly (e.g. using LatticeProteins: pnat). Names that are not listed here are internal and may change in any release.

LatticeProteins.LatticeProteins — Module
LatticeProteins

Simulate the lattice proteins model on a 3×3×3 cubic lattice in Julia.

A lattice protein is a simplified model where a protein sequence of 27 amino acids folds on a 3×3×3 cubic lattice. The energy of a sequence in a given structure is determined by pairwise contacts using the Miyazawa-Jernigan interaction matrix. The probability that a sequence folds into a structure is a Boltzmann distribution over a set of competing compact structures (StructureSet): by default all 103,346 compact structures of the lattice (STRUCTURES), or optionally the representative subset of 10,000 structures of Heo, Maslov & Shakhnovich (2011) used by Jacquin et al. (2016) (shakhnovich_structures).

The package exports no names. Its public API is the list of names declared public (see names(LatticeProteins)); everything else is internal and can change in any release.

References

  • Jacquin, Hugo, et al. "Benchmarking inverse statistical approaches for protein structure and design with exactly solvable models." PLoS computational biology 12.5 (2016): e1004889.

Sequences

Sequences are strings over the alphabet AMINO_ACIDS, integer-coded vectors (potts) or one-hot encoded arrays (onehot). Energies and samplers work with integer-coded sequences.

LatticeProteins.AMINO_ACIDS — Constant
AMINO_ACIDS

Amino acid alphabet string used for encoding: "CMFILVWYAGTSNQDEHRKP-" (20 amino acids plus a gap character). This ordering follows the convention used in the lattice proteins literature.

Structures

A StructureSet is a set of structures competing to fold a sequence. Functions take it as the keyword argument structures, and refer to a structure by its index in the set.

LatticeProteins.StructureSet — Type
StructureSet(contact_maps)

A set of structures competing to fold a sequence. contact_maps is a vector with one contact map per structure: a matrix of size (ncontacts, 2) whose rows are the pairs of residue positions (in 1:27) in contact. All structures must have the same number of contacts.

The functions that depend on the folding probability (pnat, metropolis!, parallel_tempering, ...) take the set of competing structures as the keyword argument structures, and refer to a structure by its index in that set. The package provides two sets:

  • STRUCTURES: all 103,346 compact structures of the lattice (the default);
  • shakhnovich_structures(): the subset of 10,000 structures used by Jacquin et al. (2016).

length(S) is the number of structures of a set S, contact_map(S, s) the contact map of its structure s, and structure_index finds a structure in a set, which translates indices between sets.

Example

# two structures with a single contact each
S = StructureSet([[1 4], [1 6]])
pnat(1, seq; structures = S)
source
LatticeProteins.STRUCTURES — Constant
STRUCTURES

The StructureSet of all 103,346 compact structures of a 27-mer on the 3×3×3 cubic lattice, as generated by enumerate_structures.

This is the default set of competing structures in pnat, metropolis! and related functions. See shakhnovich_structures for the representative subset of 10,000 structures used by Jacquin et al. (2016).

source
LatticeProteins.shakhnovich_structures — Function
shakhnovich_structures()

The StructureSet of the representative subset of 10,000 compact structures selected by the Shakhnovich group (Heo, Maslov & Shakhnovich, 2011) out of the 103,346 of STRUCTURES, and used as the set of competing structures by Jacquin et al. (2016) and Tubiana et al. (2019).

Pass structures = shakhnovich_structures() to pnat, metropolis! and related functions to compete only against this set, as in those papers and in the Hugo_MSA_pnat values. Structure indices refer to the set in use; use structure_index to translate between the two sets. For example, structure_index(shakhnovich_structures(), STRUCTURE_A) gives the index (625) of reference structure A in this set.

The contact maps are downloaded the first time this function is called, and the set is built once per session.

References

  • Heo, M., Maslov, S., and Shakhnovich, E. "Topology of protein interaction network shapes protein abundances and strengths of their functional and nonspecific interactions." Proceedings of the National Academy of Sciences 108.10 (2011): 4258-4263.
  • Jacquin, H., et al. "Benchmarking inverse statistical approaches for protein structure and design with exactly solvable models." PLoS Computational Biology 12.5 (2016): e1004889.

LatticeProteins.structure_index — Function
structure_index(S::StructureSet, cm::AbstractMatrix)
structure_index(S::StructureSet, s::Integer; from = STRUCTURES)

Index within the set S of the structure with contact map cm, or nothing if it is not there. cm is a matrix of contact pairs as returned by contact_map; the order of the contacts and the order within each pair are ignored.

The second method looks for structure s of the set from (by default STRUCTURES), and so translates structure indices from one set to another.

Example

S10 = shakhnovich_structures()
a = structure_index(S10, STRUCTURE_A)  # 625: index of structure A in the subset
pnat(a, seq; structures = S10)

LatticeProteins.enumerate_structures — Function
enumerate_structures()

Enumerate all maximally compact structures of a 27-mer on the 3×3×3 cubic lattice, that is, all self-avoiding walks visiting the 27 lattice sites, modulo the 48 rotations and reflections of the cube. There are 103,346 of them. The chain direction is kept: reversing the chain maps contact (i, j) to (28 - j, 28 - i), which in general gives a different contact map, so a structure and its chain reversal count as distinct structures (62 of them are their own reversal).

Returns a StructureSet. Each contact map lists its 28 contacts as rows (i, j) with i < j, sorted lexicographically. The enumeration order is deterministic. Takes about a second.

The result is available pre-computed as STRUCTURES, which is the default set of competing structures; this function is only needed to regenerate it.

References

  • Shakhnovich, E. I., and A. M. Gutin. "Enumeration of all compact conformations of copolymers with random sequence of links." The Journal of Chemical Physics 93.8 (1990): 5967-5971.

LatticeProteins.MJ — Constant
MJ

The 20×20 Miyazawa-Jernigan contact energy matrix (a Matrix{Float64}). Element (a, b) is the interaction energy between amino acids a and b, indexed in the order of AMINO_ACIDS (its first 20 characters, that is, without the gap).

LatticeProteins.energy — Function
energy(s, seq; structures = STRUCTURES)

Contact energy of amino acid sequence seq in structure s: the sum of the Miyazawa-Jernigan interaction energies (MJ) over the pairs of residues in contact in that structure.

seq is a vector of length 27 of amino acid indices in 1:20 (see potts). s is the index of the structure in the StructureSet structures, which defaults to all compact structures STRUCTURES.

energies(seq; structures = STRUCTURES)

Contact energies of seq in every structure of structures, as a Vector{Float64} of length length(structures). Equivalent to [energy(s, seq; structures) for s in 1:length(structures)], but faster.

source
LatticeProteins.log_pnat — Function
log_pnat(s, seq; structures = STRUCTURES)

Log-probability that sequence seq folds into structure s (the "native" structure), as opposed to any of the other structures in structures.

The probability is a Boltzmann distribution at temperature 1 over the structures in structures:

\[\log P_\text{nat}(s \mid \text{seq}) = -\log \sum_{s'} \exp\bigl(E(s, \text{seq}) - E(s', \text{seq})\bigr)\]

By default structures is STRUCTURES, all 103,346 compact structures of the lattice. Pass structures = shakhnovich_structures() to sum only over the representative subset of 10,000 structures used by Jacquin et al. (2016) (see shakhnovich_structures); note that structure indices refer to the set in use.

See also pnat, energy.

Sampling

LatticeProteins.metropolis! — Function
metropolis!(seq, s; β = 1, nsteps = 1, structures = STRUCTURES, rng = default_rng())

Perform Metropolis Monte Carlo sampling on the amino acid sequence seq, targeting structure s. The sequence is mutated in place, and returned.

Each step proposes to mutate a random position to a different amino acid, chosen uniformly among the other 19. The move is accepted or rejected using the Metropolis criterion with inverse temperature β, where the energy is -log_pnat(s, seq; structures). The stationary distribution is thus proportional to pnat(s, seq; structures)^β.

The energies of seq in all structures are kept and updated incrementally after each mutation, so a step costs much less than a call to log_pnat. They are computed from scratch at the start of each call: prefer one call with a large nsteps to many short ones.

Arguments

  • seq: integer-coded amino acid sequence of length 27 (values in 1:20).
  • s: index of the target structure in structures.
  • β: inverse temperature (higher values favor sequences that fold into s).
  • nsteps: number of Monte Carlo steps to perform.
  • structures: the StructureSet of competing structures, by default all compact structures STRUCTURES.
  • rng: random number generator.

See also random_msa, parallel_tempering.

source
LatticeProteins.random_msa — Function
random_msa(s; nseqs = 1, β = 1, nsteps = 1000, structures = STRUCTURES, rng = default_rng())

Generate a random multiple sequence alignment (MSA) of nseqs sequences that fold into structure s, using Metropolis Monte Carlo sampling.

Each sequence is initialized randomly and then evolved independently for nsteps Metropolis steps at inverse temperature β (see metropolis!). Returns a Matrix{Int} of size (27, nseqs), where each column is an integer-coded amino acid sequence.

See also metropolis!, parallel_tempering.

LatticeProteins.parallel_tempering — Function
parallel_tempering(s; betas, nseqs=100, burnin=1000, thin=10, local_steps=10,
                   initial_seqs=nothing, rng=default_rng(), structures=STRUCTURES,
                   threaded=true, rng_mode=:per_temperature)

Sample sequences with replica exchange, targeting pnat(s, seq; structures)^betas[end]. betas must contain at least two finite, nonnegative, strictly increasing inverse selection temperatures (hot to cold). The physical folding temperature stays at 1; all 103,346 compact structures are included by default, just as in log_pnat. Pass structures=shakhnovich_structures() for the 10,000-structure subset used by Jacquin et al. (2016). s indexes the selected set; use structure_index to translate it.

One round performs local_steps Metropolis steps per replica (the moves of metropolis!), then proposes swaps on alternating disjoint adjacent edges. For two replicas the only edge is attempted every round. A swap is accepted with min(1, exp((betas[i]-betas[j]) * (E[i]-E[j]))), where E = -log_pnat.

Discard burnin rounds, then save the coldest sequence after every thin rounds until nseqs samples have been saved. Thus each replica receives (burnin + nseqs * thin) * local_steps mutation proposals. initial_seqs, when provided, is a (27, length(betas)) integer matrix, ordered hot to cold; it is copied. Otherwise each replica starts from an independent uniform sequence. Use an explicit RNG for reproducible runs. By default, each temperature slot uses its own Xoshiro stream seeded from rng; swaps use rng serially. For fixed arguments and Julia version, results do not depend on thread count or scheduling.

With threaded=true, local updates run on Julia's default thread pool (start Julia with e.g. --threads=4). Set threaded=false when parallelizing independent ladders in the caller. Both modes use the same per-temperature streams and produce identical results.

rng_mode=:shared with threaded=false uses rng for both local updates and swaps, without creating temperature streams. This makes a run resumable: a call with burnin=0 that passes the same RNG and the final_seqs of the previous call continues its trajectory exactly, provided the previous call ended on an even number of rounds (which preserves the alternation of the swap edges). It is also the RNG protocol of v2.1.0 and of the saved Tubiana PT alignment. The default :per_temperature mode creates fresh local streams on each call and is not a checkpoint interface.

Returns a named tuple with:

  • samples: coldest-replica MSA, size (27, nseqs). Samples can be correlated.
  • betas: the fixed ladder used in the run.
  • rng_mode: the RNG protocol used (:per_temperature or :shared).
  • log_pnat, replica_ids: (length(betas), nseqs) traces at saved rounds. Rows follow temperatures; IDs follow sequences through swaps.
  • final_seqs, final_log_pnat: final states at every temperature.
  • burnin_diagnostics, diagnostics: separate burn-in and production counters. local_attempts/local_accepts are indexed by temperature; swap_attempts/swap_accepts by adjacent edge. round_trips is indexed by replica ID and counts completed hot→cold→hot trips entirely within that phase.

Inspect swap acceptance, round trips, and agreement between independent runs. High folding probabilities or accepted swaps alone do not establish equilibrium. Tune the ladder in pilot runs, then hold it fixed for production sampling.

See also metropolis!, random_msa.

LatticeProteins.Hugo_MSA_pnat — Function
Hugo_MSA_pnat(which::Symbol)

Load the native fold probabilities (pnat values) for the reference MSA dataset from Jacquin et al. (2016). which must be one of :A, :B, :C, or :D. Returns a Vector{Float64}. These values were computed against the subset of 10,000 structures, i.e. pnat(s, seq; structures = shakhnovich_structures()) with s the index of the structure in shakhnovich_structures.

See also Hugo_MSA.

source
LatticeProteins.Hugo_MSA_path — Function
Hugo_MSA_path(which::Symbol)

Return the file path to one of the reference MSA datasets from Jacquin et al. (2016). which must be one of :A, :B, :C, or :D, corresponding to the four reference structures (STRUCTURE_A, etc.). Each line of the file holds the inverse temperature used for sampling, the folding probability and the sequence.

The files are downloaded the first time one of them is requested.
